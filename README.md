# Dungeon Sandbox

An original Rust + Bevy 0.20 third-person dungeon RPG inspired by the
*mechanical feel* of classic tab-target MMORPG dungeons: one player, four
autonomous companions (tank / healer / DPS) with selectable AI personalities,
a WoW-Classic-style combat model (armor, hit tables, rage/energy/mana,
interrupts, crowd control), six data-driven dungeons (two generated by the
Dungeon Forge pipeline from different theme kits), a navigation test level and a 10-player raid with multi-phase bosses, layered navigation with
angled caves, ramps, bridges, drops and line of sight, levels, loot with rarities, and a sandbox for editing
encounters without recompiling. Classic MMO controls, clickable party/raid
frames with mouseover healing, threat-coloured nameplates and tooltips
generated from the real rules. A **dungeon viewer** flies through any dungeon
without playing it, with navigation, structure, encounter and art layers.
The generated dungeons are dressed with original modular stone and basalt
pieces placed along their real walls. All assets are original (primitive
meshes and script-generated GLB models); all names, maps and numbers are
original.

## Quick start

**Packaged build (Windows):** extract `DungeonSandbox-<version>-windows-x64.zip`
and double-click `dungeon-sandbox.exe`; `HOW_TO_PLAY.txt` inside explains the
game. Saves go to `saves\` next to the exe. Building the package:
[RELEASE_BUILD.md](RELEASE_BUILD.md).

**From source:**

```bash
cargo run --release
```

The first build compiles Bevy and takes several minutes. `cargo run` (debug
profile) also works; dependencies are optimised even in debug.

| Both    | A / D | turn (strafe while the right button is held) |
| Both    | Q / E | strafe |
| Both    | right-drag | rotate the camera and steer the character |
| Both    | left-drag | free look (facing unchanged); a short click selects |
| Both    | both buttons | run forward |
| Both    | arrow keys, wheel | rotate/tilt camera, zoom |
| Both    | V | camera auto-follow on/off (saved) |
| Both    | hover | tooltips on buttons, stats, items, abilities, frames |
| Hub     | mouse | click the panel buttons (recruit, AI profile, equip, dungeon, difficulty...) |
| Hub     | 1-8 / P | switch panel tab / hide panel |
| Hub     | E (at portal) | enter the selected dungeon (re-reads all content files) |
| Hub     | F5 | reload content files |
| Dungeon | Tab / Shift+Tab / click | cycle enemies (engaged first) / reverse / pick any actor |
| Dungeon | click a party frame / F1-F5 | select a party member |
| Dungeon | click the target-of-target frame / T | select your target's target |
| Dungeon | G | target the party's kill target |
| Dungeon | 1-5 | class abilities; friendly spells go to the ally under the mouse (frame or character), else your selected ally, else you |
| Dungeon | F / Esc | start auto-attack / clear target |
| Dungeon | L | toggle verbose combat log |
| Dungeon | K | show/hide your numbers for this fight (bottom right) |
| Dungeon | Backspace | leave the dungeon (counts as a failed run) |
| Dungeon | N / Shift+N | navigation debug overlay / plus walls and walk areas |
| Results | Enter | back to the hub |

In the dungeon, enemy nameplates are coloured by threat from your point of view
(tank: green secure / yellow contested / blue other tank / red lost; others:
yellow = close to pulling, red = attacking you). The action bar shows range,
cooldown (dark curtain), global cooldown (thin top bar) and resource shortfall
with the time until affordable.

Levels have height (0.4): ramps, stairs, bridges, stacked walkways and one-way
drops (orange strips at the edge). Abilities and auto attacks need line of
sight, so walls and floors block casts and heals ("no line of sight"), and an
enemy on another floor can't be hit or pulled through it.

## Dungeons

* **The Sunken Vault** (level 1+): skulker packs, a cleaving brute, and Morvane,
  the Hollow King — interruptible Hollow Bolts, then Cinder Rings at 50% HP.
* **The Gloomroot Warrens** (level 4+): healer-casters to interrupt, an optional
  spore grotto, Mother Brakkis (adds, stacking dispellable poison, frontal
  cleave), lava vents, and three-phase Vhorlag (party-wide pulses, adds, double
  rings, a stacking tank debuff).

* **The Ashen Spire** (level 8+): healing-reduction brands, armored sentinels,
  a fire-jet corridor, the Twin Altar council (two bosses at once), an optional
  Furnace Golem, and three-phase Ashmaw.
* **The Cinder Court** (raid, 10 players, level 10): gate guards, Twinmaw the
  Behemoth (tank swaps) and the Cinder Regent.

* **The Cinderdeep Hollows** (level 5+, 0.5): an original lava-cavern descent
  from a cold entrance to a molten heart: a fork into a low road and a high
  ridge (with a one-way drop), Kilnmaster Vorsk beside a slag pit, an optional
  Glass Matriarch, the Kiln Span bridge over a lava river, the Magma Cistern
  and Ignarax, the Molten Heart, on an island in a lava moat. Three optional
  fights, a return tunnel. See [DUNGEON_0_5.md](DUNGEON_0_5.md) and
  [PLAYTEST_0_5.md](PLAYTEST_0_5.md).

* **The Emberforge Vaults** (level 3+, 0.6): the first dungeon built by
  Dungeon Forge from a blueprint, not by hand. Emberkin raiders, a guarded
  pyrecaller, Forgewarden Hask at a lava pit and Cindermaw, the Furnace Wyrm.
  It has an alternate route, an overlook with a one-way drop, a lava bridge,
  and an optional elite in a side cell. Regenerated in 0.7 with irregular
  caverns, longer passages and an ash-hound patrol. Two more layouts of the
  same blueprint are in `assets/content/variants/forge/`. See
  [PLAYTEST_FORGE.md](PLAYTEST_FORGE.md).

* **The Hollow Reliquary** (level 4+, 0.7): the second generated dungeon, from
  a different kit. The buried monastery of the Hushed has:
  * narrow passages and naves with solid pillars that block movement and
    sight;
  * a shield wall guarding healers, a sentinel patrol, and bone archers to
    pull round a pillar;
  * the Twin Abbots (a council);
  * the Hollow Guardian, whose wail only hits those who can see it: hide
    behind the pillars.

  Two more layouts are in `assets/content/variants/forge/`. See
  [DUNGEON_FORGE_0_7.md](DUNGEON_FORGE_0_7.md).

* **Cavern Traverse** (level 2+, 0.4): a graybox navigation proving ground with
  a winding passage, a ramp to a high walkway, a rope bridge over an underpass,
  a gallery stacked above it, a one-way drop into the Magma Basin, a narrow
  tunnel, a lava pit and a fire vent. See
  [PLAYTEST_NAVIGATION.md](PLAYTEST_NAVIGATION.md).

Each has Normal, Heroic and Raid (10) difficulties; the Party tab switches
between a 5-person party and a 10-person raid group. The Sandbox tab adjusts
enemy health, damage, ability speed and telegraph time without editing files,
and holds the **Class Design Lab** (0.10): two experimental Striker styles,
for this session only (CLASS_DESIGN_LAB_0_10.md, PLAYTEST_CLASS_LAB_0_10.md);
the Editor tab tunes individual bosses and abilities and saves a custom dungeon
file. The Vendor sells gear for Vault Marks and buys back what you don't need.
Companions grow more familiar with dungeons they clear and react faster there. Bosses and elites drop loot; kills and
clears give XP (levels 1–10). Your companions level and gear up with you.

## Editing encounters (no recompile)

Every dungeon is a TOML file in [`assets/content/dungeons/`](assets/content/dungeons/):
layout, enemy templates (stats, abilities, phases, enrage), encounters (mobs,
hazards, optional), difficulties, loot and rewards. Change a boss timer, add a
phase, swap a mob, then press **F5** in the hub or just enter the portal.
Example variants live in [`assets/content/variants/`](assets/content/variants/)
(copy one into `dungeons/` to play it). Invalid files are rejected with every
problem listed by field, for example:

```
content file 'assets/content/dungeons/01_sunken_vault.toml' has 2 problem(s):
  - dungeon.hp_multiplier = -3 is out of range; use a value between 0.05 and 20.0 (1.0 = normal)
  - encounters[0].mobs[0].template 'skulkr' is not defined; known templates: brute, hollow_king, skulker
```

Enemy ability kinds: `bolt`, `cleave` (optionally `frontal`), `ring`, `pulse`,
`summon`, `debuff` (dot / damage_taken / healing_taken), `heal_ally`. See
RULES.md for every field.

Heights (0.4, all optional; old files load unchanged at height 0):

```toml
[[dungeon.areas]]
name = "Ash Ramp"
min = [14.0, 47.0]
max = [20.0, 61.0]
y = 0.0          # height (at the min edge for a ramp)
y_to = 5.0       # makes it a ramp; axis = "z" (default) or "x"; stairs = true draws steps

[[dungeon.areas]]
name = "Rope Bridge"
min = [19.0, 68.0]
max = [47.0, 72.0]
y = 5.0
under = "open"   # a deck you can walk under (default "solid" = rock down to the floor)
walls = false

[[dungeon.links]]  # one-way drop: zone straddles the upper area's edge
from = "Hanging Gallery"
to = "Magma Basin"
kind = "drop"
min = [40.0, 96.5]
max = [46.0, 99.5]
```

Caves (0.5): areas can be convex polygons and ramps can run in any
direction; lava pools/rivers can be polygons; scenery and lights are data:

```toml
[[dungeon.areas]]
name = "Glass Passage"
points = [[-14.6, 94.4], [-30.0, 96.7], [-29.3, 101.7], [-13.9, 99.4]]
y = -4.0
y_to = -1.0
slope_from = [-15.0, 97.0]   # height y here ...
slope_to = [-28.9, 99.1]     # ... and y_to here

[[dungeon.decor]]   # pillar | stalagmite | boulder | crystal; must not overlap walkable floor
kind = "stalagmite"
pos = [6.0, 20.0]
radius = 0.8
height = 3.0

[[dungeon.lights]]
pos = [8.0, 88.0]
y = -2.0
color = [1.0, 0.5, 0.2]
intensity = 1.2      # relative brightness (1.0 = normal)
range = 18.0
```

Areas connect only where they overlap **and** are level with each other.
Mob and hazard positions take an optional `y` (required when floors are
stacked there). The full rules are in RULES.md ("Navigation" and its 0.5
additions); the design is in [NAVIGATION_0_4.md](NAVIGATION_0_4.md) and
[DUNGEON_0_5.md](DUNGEON_0_5.md).

Environment overrides: `DUNGEON_CONTENT=<dir or file>`,
`DUNGEON_SAVE_DIR=<dir>` (default `./saves`).

## Dungeon viewer (0.8, 0.8.1)

Inspect a dungeon without recruiting, entering or fighting. It uses the
game's own renderer, and creates no simulation and writes no save.

```powershell
.\target\release\dungeon-sandbox.exe --viewer hollow_reliquary
.\target\release\dungeon-sandbox.exe --viewer assets\content\variants\forge\emberforge_vaults_s6.toml --layers nav,structure
.\target\release\dungeon-forge.exe view assets\forge\blueprints\hollow_reliquary.toml --seed 7
.\target\release\dungeon-sandbox.exe --viewer emberforge_vaults --viewer-tour   # contact sheet + frame stats
```

In the game, press V in the hub (or "Inspect in viewer" on the Dungeons
tab); Backspace returns.

| Keys | Action |
|---|---|
| Right mouse + WASD, E/Q | Fly; Shift/Ctrl change speed |
| 7 / 8 / 9, − / =, wheel | Speed presets (slow, normal, fast), fine steps (shown in the speed bar) |
| M | 2D map of the whole dungeon: zoom, pan, click a room to go there |
| I | Inspection lighting (no fog, neutral light) for overhead views |
| G, O | Walk at eye height, orbit |
| Home, Tab, L | Entrance, next room, room list |
| 1–4 | Navigation, structure, encounter and module layers |
| Click | Inspect |
| F5, [ ], F12 | Reload, other seeds, screenshot |

Everything else is in [DUNGEON_VIEWER_GUIDE.md](DUNGEON_VIEWER_GUIDE.md).

## Dungeon Remix (0.9): same dungeon, different adventure

The two forge dungeons (The Hollow Reliquary and The Emberforge Vaults) can
be played as shipped or remixed. Their encounters, bosses, theme and
completion rules stay the same. Rooms, routes, side branches and pack
placement change by seed.

In the hub's **Dungeons** tab, select a forge dungeon and use the
**Layout** row:
* **Classic**: the shipped layout.
* **Remix (new seed)**: a new random seed. If it can't be built, another is
  rolled and the skipped seeds are named.
* **Seed**: click, type a number, press Enter. The same seed always builds
  the same layout. A seed that can't be built is reported, and the classic
  layout stays selected.

The layout is shown in the hub, the HUD, the results screen and the run log
(`logs/last_run.log`). New layouts are built by `dungeon-forge` (shipped
beside the game) into `generated/` next to the save file. Progress, loot and
companions carry over, because the dungeon keeps its id.

Every branch in a 0.9 layout has a purpose:
* **reward detours** hold an optional fight and/or a treasure cache, and
  rejoin the main route further on;
* **flanks** are side passages into a required pack's room, from the side or
  behind;
* **safe ways** go round a crossing that pulses with magma vents
  (Emberforge);
* **side chambers** hold an optional fight, a cache, a landmark, or are
  deliberately quiet.

Nothing goes round a required fight or a boss. Doorways into branches carry
clues (a glowing tablet or lamp, a dim candle at a side passage). Treasure
caches open when you walk up to them, and their loot is added at the end of
the run like an encounter's. DUNGEON_REMIX_0_9.md has the design and the
measurements, and PLAYTEST_REMIX_0_9.md a script for comparing layouts.

```bash
cargo run --release -p dungeon_forge -- audit assets/forge/blueprints/hollow_reliquary.toml --layouts 1..100 --json forge_out/audit.json
cargo run --release -p dungeon_forge -- routes assets/forge/blueprints/hollow_reliquary.toml --seed 14 --runs 8
```

`audit` reports what every branch is for over many layouts and whether it
delivers it; it exits 2 on purposeless or broken branches. `routes` plays
each route choice of a layout (direct, every detour, flank and safe way)
with a scripted leader and companions on their normal AI. It reports wins,
time, deaths, hazard damage, the flanked fight against the same pack
approached directly, whether the party walked the branch, and navigation
trouble.

## Dungeon Forge (generated dungeons, 0.6–0.9)

Dungeon Forge builds original dungeons from a **blueprint** and a **kit**, then
validates them:
* the **blueprint** says what you want: level, group size, encounter order,
  extra rooms, descents, alternate routes, a shortcut, bridges, winding,
  straightness, side rooms. Its `[identity]` names the challenges it
  promises (interrupts, line of sight, patrols, a council...), and validation
  checks that some encounter delivers each one;
* the **kit** is a theme library:
  * its spatial vocabulary (grid pitch, corridor widths, room shapes such as
    pillared halls or lava pits, the chasm under bridges);
  * enemy templates;
  * encounter recipes with tags, formations, placement preferences, space
    requirements and patrols;
  * loot, palette and props.

  Two kits ship: volcanic and crypt;
* every result passes the game's loader, structural checks (no accidental
  connections, one-way drops, everything reachable) and encounter-space
  checks, and can be put through simulated party clears.

The output is an ordinary dungeon file. Handwritten dungeons are unaffected.

```bash
cargo run --release -p dungeon_forge -- validate assets/forge/blueprints/emberforge_vaults.toml
cargo run --release -p dungeon_forge -- generate assets/forge/blueprints/emberforge_vaults.toml --seed 7 --map forge_out/s7.svg
cargo run --release -p dungeon_forge -- test assets/forge/blueprints/emberforge_vaults.toml --layouts 1..10 --runs 5 --sizes 5,10
cargo run --release -p dungeon_forge -- inspect assets/content/dungeons/06_cinderdeep_hollows.toml --map forge_out/cinderdeep.svg
cargo run --release -p dungeon_forge -- seeds assets/forge/blueprints/emberforge_vaults.toml --count 40
cargo run --release -p dungeon_forge -- report assets/forge/blueprints/hollow_reliquary.toml --layouts 1..3 --runs 5 --classes striker,mender --json forge_out/report.json --svg forge_out/maps
cargo run --release -p dungeon_forge -- generate assets/forge/blueprints/hollow_reliquary.toml --overrides my_edits.toml
```

`report` shows where parties struggle: per encounter pulls, resets, wipes,
deaths, killing blows and clear times; dithering and stuck recoveries per
room; with SVG maps marking deaths and trouble spots. `--overrides` (a proof
of concept) re-applies a designer's patch, keyed by encounter ids and names,
each time the dungeon is regenerated.

`generate --tagged --out assets/content/dungeons/50_x.toml` installs a seed
under its own id, so several layouts can be played side by side. The same
blueprint and seed always produce the same file. Formats, components,
validation and measured results: [DUNGEON_FORGE_0_6.md](DUNGEON_FORGE_0_6.md)
(foundation), [DUNGEON_FORGE_0_7.md](DUNGEON_FORGE_0_7.md) (kit
components, identity, Recipes 2.0, the crypt, report, overrides) and
[DUNGEON_PRESENTATION_0_8.md](DUNGEON_PRESENTATION_0_8.md) (rooms in the
file, modules, anchors, atmosphere).
The plan: [DUNGEON_FORGE_PLAN.md](DUNGEON_FORGE_PLAN.md).

Props (0.6): `[[dungeon.props]]` places a glTF/GLB model from `assets/models/`
(`model`, `pos`, `y`, `yaw`, `scale`, `radius`, `height`) with a primitive
`fallback`, drawn when the file is missing. Props are scenery and are kept
off walkable floor. Model licensing is recorded in
`assets/models/PROVENANCE.md`; see
[ASSET_PIPELINE_RESEARCH.md](ASSET_PIPELINE_RESEARCH.md).

## Headless simulation and AI evaluation

```bash
cargo run --release -p dungeon_sim --bin dungeon-headless -- --runs 20
cargo run --release -p dungeon_sim --bin dungeon-headless -- --dungeon gloomroot_warrens --level 4 --runs 100 --compare-profiles
cargo run --release -p dungeon_sim --bin dungeon-headless -- --dungeon gloomroot_warrens --level 4 --runs 50 --breakdown --quiet
cargo run --release -p dungeon_sim --bin dungeon-headless -- --party-size 25 --level 6 --dungeon gloomroot_warrens --runs 5 --bench --quiet
cargo run --release -p dungeon_sim --bin dungeon-headless -- --lab --dungeon cinderdeep_hollows --runs 20 --levels 3,6
```

`--lab` (0.10) compares the three Striker styles (Classic, A: Planned,
B: Reactive) × three scripted ways of playing the player's slot (passive,
simple, expert) on the same seeds. It reports:
- player and party DPS by fight type;
- wins, deaths and interrupts;
- energy at the cap and ability use;
- for A, Edge wasted; for B, openings and Exploits;
- when each style gets its payoff.

`--lab-feel` plays each style step by step and reports moment-to-moment
proxies:
- presses per minute, idle and waiting time;
- gaps between non-filler presses;
- repetition;
- for A, Edge at each spend and builders from behind;
- for B, opening age and openings missed, at several simulated reaction
  times.

Options: `--dungeon ID`, `--content PATH`, `--difficulty ID`, `--class`,
`--level N` (default: the dungeon's recommended level), `--profile
conservative|balanced|aggressive|support|mechanic`, `--compare-profiles`,
`--breakdown` (damage by source, enemies turning on non-tanks, killing blows),
`--party-size N`, `--bench`, `--log FILE`, `--json`, `--quiet`. Summaries
include win rate, clear time, deaths, DPS, avoidable damage, interrupt rate,
threat failures, overheal and healing per mana; the first seed is replayed to
check determinism (exit code 3 on mismatch).

## Developer flags (graphical build)

```bash
cargo run -- --demo --dungeon gloomroot_warrens --level 6 --speed 4 --screenshots 3 --smoke-test 110
```

* `--demo` enters the portal and lets the AI play your slot (`--dungeon`,
  `--difficulty`, `--level` override the selection).
* `--speed X`, `--screenshots S` (to `screenshots/`), `--smoke-test N` (exit after N s).
* `--input-test` scripted keyboard sequence through the real input systems →
  `logs/input_test.txt`.
* `--hub-tour` screenshots every hub tab; `--click-test` clicks a hub button with
  synthetic mouse events → `logs/click_test.txt`; `--editor-test` edits and saves
  a custom dungeon through the editor (point `DUNGEON_CONTENT` at a scratch copy
  of `assets/content/dungeons`) → `logs/editor_test.txt`.
* `--frame-test` plays a Mender, hovers a party frame and presses 1 with an
  enemy selected (mouseover heal), then clicks another frame →
  `logs/frame_test.txt`; `--tooltip-test` hovers a stat and a vendor item →
  `logs/tooltip_test.txt`.
* `--class warden|mender|striker|arcanist`, `--group 10` and `--profile
  aggressive|conservative|balanced|support|mechanic` pick the player class, group
  size and every companion's AI profile for `--demo`. Threat alerts are also
  written to the log ("threat alert at ...").

* `--nav-debug` starts with the navigation overlay on; `--zoom D` sets an
  overview camera distance for screenshots, e.g.
  `--demo --dungeon cavern_traverse --nav-debug --zoom 30 --screenshots 3`.
* `--area-tour "Area A,Area B"` (or `all`) with `--dungeon ID`: points the
  camera at each named area in turn, saves `screenshots/area_NN_<name>.png`
  and exits.
* `--start-level N` raises the player and all companions to level N in the
  loaded save (never lowers), for playing higher-level dungeons in a playtest.

Manual playtest scenarios: [PLAYTEST_FORGE.md](PLAYTEST_FORGE.md) (generated dungeon and tools),
[PLAYTEST_0_5.md](PLAYTEST_0_5.md) (Cinderdeep),
[PLAYTEST_0_3.md](PLAYTEST_0_3.md) (combat UX) and
[PLAYTEST_NAVIGATION.md](PLAYTEST_NAVIGATION.md) (0.4 navigation).

Set `DUNGEON_SAVE_DIR` to a temp folder for these runs so they don't touch your
real profile.

`cargo test -p dungeon_sim --release diag_replay -- --ignored --nocapture`
replays one headless run and prints every actor's position, surface, goal and
waypoint (`DIAG_DUNGEON`, `DIAG_SEED`, `DIAG_LEVEL`, `DIAG_SIZE`,
`DIAG_CLASS`, `DIAG_TIME`; `DIAG_WATCH=<actor>` with `DIAG_N=<ticks>` traces

and every party member's position, goal and visibility every half second;
`DIAG_ALL` includes idle enemies).

## Layout

```
crates/sim    dungeon_sim: stats & formulas, combat, auras, AI + blackboard,
              layered 2.5D navigation on convex polygons + line of sight,
              content schema, items, profile/progression, headless runner
crates/forge  dungeon_forge: blueprint/kit formats, layout generator, components,
              placement scorer, validation, simulation matrix, report,
              overrides, maps (dungeon-forge CLI)
crates/game   dungeon_game: Bevy app (hub, environment renderer env.rs + modules.rs,
              dungeon play, viewer.rs, structure.rs, HUD, overlays, effects,
              results, camera, controls, tooltips, demo/test automation)
assets/content/dungeons/   the playable dungeons (TOML)
assets/content/variants/   example encounter variations
packaging/    files shipped in the Windows package (HOW_TO_PLAY.txt)
scripts/      package-windows.ps1, make_prop_models.py
assets/forge/ kits (theme libraries), blueprints, maps of shipped layouts
assets/models/ glTF/GLB props, modular kit pieces (kit/) + PROVENANCE.md
RULES.md      authoritative rules and formulas ([WoW] / [orig] tagged)
RESEARCH.md   references and design provenance
PROGRESS.md   verified status, benchmarks, known problems
TASKS.md      prioritized next work
CHANGELOG.md  meaningful changes
```
